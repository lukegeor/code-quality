# LG0001: Avoid Null-Forgiving Operator

| Property | Value |
| --- | --- |
| **Rule ID** | `LG0001` |
| **Title** | Avoid null-forgiving operator |
| **Category** | `Reliability` |
| **Default Severity** | `Warning` |
| **Enabled by Default** | Yes |
| **Code Fix Available** | Yes |

## Cause

The null-forgiving operator (`!`) was used to suppress compiler nullability warnings.

## Rule Description

The null-forgiving operator (`!`) overrides the C# compiler's static null-state analysis without performing any runtime validation or structural safety guarantees. Using `!` masks potential `NullReferenceException` crashes at runtime.

Instead of suppressing warnings, code should address nullability structurally using:
- Pattern matching (`is not null`, `if (val is { } nonNull)`)
- Explicit constructor initialization
- Null-conditional operators (`?.`) and fallback defaults (`??`)
- Explicit null validation and error throwing where appropriate

## How to Fix Violations

Remove the null-forgiving operator (`!`) and handle potential null states explicitly.

### Non-Compliant Example

```csharp
#nullable enable
public class Sample
{
    public void Process(string? input)
    {
        // Violation: suppresses compiler check
        int length = input!.Length;
    }
}
```

### Compliant Solutions

```csharp
#nullable enable
public class Sample
{
    public void ProcessWithPatternMatching(string? input)
    {
        if (input is { } nonNullInput)
        {
            int length = nonNullInput.Length;
        }
    }

    public void ProcessWithNullConditional(string? input)
    {
        int? length = input?.Length;
    }
}
```

## How to Suppress Violations

If suppression is strictly necessary, use `#pragma warning disable LG0001` or configure `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.LG0001.severity = none
```
